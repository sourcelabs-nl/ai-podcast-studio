## Context

35 of 48 sources point at `nitter.net`, which is decommissioned. The application-side detection for this (the host circuit breaker) landed in `add-source-host-circuit-breaker`; this change restores the content those sources were carrying.

Nitter has not been usable through public instances since X removed guest accounts in 2024. The project itself is alive — `zedeus/nitter` had commits on 2026-08-22 fixing Cloudflare blocks and refreshing GraphQL endpoint hashes, and the Docker image was rebuilt on 2026-08-24 — but every instance now needs a session from a registered account.

## Goals / Non-Goals

**Goals:**
- Restore the 35 X accounts as article sources at no monetary cost.
- Keep the deployment small, private, and unprivileged.
- Preserve source ids so article history and episode links survive.
- Make the inevitable next breakage visible immediately.

**Non-Goals:**
- A public or shared Nitter instance. That is what X's countermeasures target.
- Automating burner account creation or session generation. Those need the operator's own credentials.
- Replacing the `TWITTER` source type. It remains the sanctioned fallback if this becomes untenable.

## Decisions

### Decision 1: Upstream image, not a fork

`zedeus/nitter:latest-arm64`, the official image, rebuilt the same week as this change. The `sekai-soft` fork exists and its guide is useful, but its own guide now points back at upstream, and upstream is the one receiving the Cloudflare and GraphQL fixes.

ARM64 is pinned explicitly because the target machine is Apple Silicon; x86_64 hosts use `zedeus/nitter:latest`.

### Decision 2: Repoint through the REST API, not the database

The script rewrites URLs via `PUT /users/{userId}/podcasts/{podcastId}/sources/{sourceId}`, per this project's rule that production data is changed through the API.

Two properties fall out of that choice and are worth having: source ids are preserved, so `episode_articles` links and per-source article history stay intact; and the update path already resets failure counters when a source is re-enabled, so the 35 sources come back on their normal 30-minute interval rather than sitting on the 24-hour backoff they accumulated while dead.

The endpoint replaces a source's configuration wholesale, so the script re-sends every field rather than only the URL. Omitting `label` or `pollIntervalMinutes` would silently reset them.

*Alternative considered:* a SQL `UPDATE` over the `sources` table. Faster to write, but bypasses the API rule, skips the failure-counter reset, and would need the app restarted to pick up the change.

### Decision 3: The session file is a manual, git-ignored artefact

`sessions.jsonl` is generated by the operator with `tools/create_sessions_browser.py` and never committed. It is a logged-in X session, functionally a credential.

The browser-driven tool is documented as the primary route because the older direct-API flow (`get_session.py`) is intermittently Cloudflare-blocked, which is what the recent upstream commits address. Both are documented, since either may be the working one on a given week.

### Decision 4: Bind to loopback, drop every privilege

The instance serves exactly one client on the same machine. It binds `127.0.0.1`, runs as a non-root user with a read-only root filesystem, `no-new-privileges`, and all capabilities dropped. Port 8081 avoids the common 8080 collision; the app is on 8085 and the frontend on 3005.

RSS is narrowed to user timelines only. Replies, media, search and list feeds are disabled: the application reads none of them, and each is load on a session X is willing to rate-limit.

## Risks / Trade-offs

- **The burner account is locked or suspended** → expected, not hypothetical; reports put it at roughly a month for accounts without 2FA. Mitigation: 2FA is recommended in the README, `sessions.jsonl` accepts multiple accounts, and replacing a session is a documented step rather than a rediscovery.

- **X breaks Nitter again** → certain, on a timescale of weeks. Mitigation: the host circuit breaker makes it loud within one poll round, and recovery is an image pull. This is the failure mode this whole line of work exists to surface.

- **Automated reading violates X's ToS** → accepted deliberately, at personal scale, with a disposable account and no redistribution. The sanctioned alternative (pay-per-use API, roughly $25-50/month for this volume) remains available and is a source-type change away, since `TwitterFetcher` and its OAuth flow already exist.

- **A local hostname means every source shares the host `localhost`** → this is desirable here (one breaker for the whole instance) but means a future non-Nitter source on `localhost` would share that breaker. No such source exists or is planned.

## Migration Plan

1. Operator sets `hmacKey` and creates `sessions.jsonl` from a burner account.
2. `docker compose -f docker/nitter/docker-compose.yml up -d`.
3. Verify: `curl -s http://localhost:8081/sama/rss` returns items.
4. `./scripts/repoint-nitter-sources.sh http://localhost:8081` (dry-run first).
5. Confirm from `app.log` that the repointed sources save posts on the next round.

Rollback is the same script pointed back at `https://nitter.net`, plus stopping the containers. Nothing in the application changes, so no redeploy is involved.

None blocking. Whether to keep this or move to the paid API is a cost/effort judgement the operator can revisit at any time without further code changes.
